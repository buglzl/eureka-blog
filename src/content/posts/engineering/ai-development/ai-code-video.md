## 一、先决定让 AI 承担哪部分工作

“AI 做视频”描述的是结果。要选择工具，先看你手里有什么，以及希望得到什么。下面是三种常见的切入方式。

| 路线 | 输入与制作动作 | 适合的内容 |
| --- | --- | --- |
| 视频模型生成 | 输入描述或参考素材，由模型生成连续镜头 | 写实镜头、剧情片段 |
| 辅助剪辑 | 输入已有视频，转写、删改、重排和添加字幕 | 口播、访谈、录屏 |
| 代码动画 | 将分镜写成程序，绘制对象并安排它们随时间变化 | 概念讲解、产品演示、动态图表 |

例如，Descript 将转写文字与原始媒体关联，删掉或移动文字时，对应的音视频片段也随之改变。这是在处理已有素材。[官方说明](https://help.descript.com/getting-started/edit-like-a-doc)

本文选择代码动画。讲“帧号决定位置”，就让一个光点沿着刻度移动；讲“多层内容共用时间线”，就展示画面、字幕和声音的排列。**画面需要表达明确的关系，程序可以直接把这些关系写出来。**

三条路线也可以组合：生成模型提供素材，代码负责图表和字幕，剪辑工具再处理其他镜头。这里先完成一条尽量清楚的制作链。

## 二、代码为什么能成为视频

### 从帧号到画面

视频由连续画面组成，每张画面叫一帧。**帧率**（frames per second，FPS）表示每秒播放多少帧。以 30 FPS 为例，从第 0 帧开始计数，第 30 帧对应 1 秒。

只要程序知道当前帧号，就可以计算物体此刻的位置。让光点从左侧移到右侧，可以写成：

```tsx
const frame = useCurrentFrame();
const progress = interpolate(frame, [0, 120], [0, 1], {
  extrapolateLeft: "clamp",
  extrapolateRight: "clamp",
});
const x = 135 + 1375 * progress;
```

这段代码把第 0～120 帧映射成 0～1 的进度，再计算水平位置。30 FPS 下，这段运动持续约 4 秒。`clamp` 让超出区间的值停在端点。

于是，修改有了具体入口：晚一点出发，改变开始帧；慢一点移动，扩大帧数区间；换一条轨迹，改变位置计算式。

### 两个工具，各自解决一个问题

**Remotion** 是用 **React** 制作视频的框架；React 是构建界面的 JavaScript 库。Remotion 提供当前帧号，让组件绘制对应画面，并安排文字、图形、媒体等内容。[核心原理](https://www.remotion.dev/docs/idea)

**Three.js** 是 JavaScript 三维图形库。本片用它绘制网格、光点和空间视角，再通过 Remotion 的三维集成把它们接入视频时间线。网格高度随时间变化，形成开头的起伏效果。[三维集成文档](https://www.remotion.dev/docs/three)

:::note[动画的表达边界]
本片的空间网格是程序绘制的视觉示意，帮助解释“画面随时间变化”。它没有进行物理建模，不能据此判断引力或波动的真实规律。
:::

如果主要内容是公式、几何或算法推导，也可以考虑 **Manim**，一个用 Python 编写程序动画的工具。先根据要表达的内容选工具，再让 AI 编写实现。[Manim 入门](https://docs.manim.community/en/stable/tutorials/quickstart.html)

## 三、把本文做成一支视频

制作链可以写成一行：

**要求 → 讲解稿 → 分镜 → 动画代码 → 配音与时间编排 → 渲染 → 审阅。**

### 先把要求写到能执行

只有“做个高级的视频”，AI 很难判断什么该动、什么该留。更有用的是说明读者、目的、视觉任务和完成条件：

```text
给有技术基础、第一次接触视频制作的读者，
解释 AI 如何编写动画代码，再由程序渲染成视频。

先简要介绍不同路线，重点讲代码动画。
每段画面承担一个解释任务：
讲帧号时展示位置变化，讲时间线时展示片段排列。

用空间网格、动态图形和清楚的中文文字建立层次。
配音、字幕与画面需要同步，导出可播放的 MP4。
结尾展示本片的制作分工，准确说明 AI 和人的工作。
```

本片按同一条论证链写出讲解稿，并拆成 15 段分镜。分镜就是逐段规定“这句话出现时，观众应该看到什么”。

| 讲解内容 | 对应的视觉任务 |
| --- | --- |
| 三种制作路线 | 三张卡片分别展示镜头、剪辑和代码动画 |
| 帧号驱动运动 | 光点沿刻度移动，显示当前帧号与时间 |
| 多层内容协作 | 画面、字幕和声音排列在同一条时间线上 |
| 修改动画参数 | 展示开始帧与持续帧数如何改变运动 |
| 导出与检查 | 展示画面、编码文件和播放检查的关系 |
| 结尾揭晓 | 回到开头的三维网格，交代这支视频的制作分工 |

### 再把分镜写成可修改的实现

代码把画面对象与时间分开组织：场景负责“画什么”，时间数据负责“何时开始、持续多久”。分镜文字、音频长度和开始帧记录在数据文件里，画面组件读取这些数据。

这让修改能落到小范围内。例如，解释运动速度时，光点的外观可以保留，只改变运动的时间区间。代码带来了修改入口；是否需要修改，仍要通过预览判断。

### 让声音决定镜头长度

先把书面文字改成能说出口的句子，选好音色，做一段短试听，再生成完整旁白。技术讲解需要清晰、稳定的声音，也需要随内容变化的语气：提问时带一点好奇，解释时平稳，结尾揭晓时轻快一些。

本片使用 **Qwen3-TTS**：先试听并选定 **Serena** 女声，再用 **Voice Clone**（声音克隆）功能，把选定的合成干声作为全片参考。干声就是没有混入背景音乐的语音。15 个场景共用同一份声音参考，中英名称也由同一声线讲述，以减少跨段音色变化。[官方用法](https://github.com/QwenLM/Qwen3-TTS#voice-clone)

**每个场景的旁白整段一次合成。** 让模型同时看到前后句，更容易保留语气衔接；逐句生成再拼接，则需要额外处理句尾收声、下一句起声和停顿。音色、文稿和段落节奏共同决定听感，换一个模型只是其中一步。

固定参考后，还要连续听不同场景，检查中英名称、句尾收声和段落切换，确认整片听起来像同一个人在连续讲解。

随后按实测音频时长计算镜头帧数，把画面安排到旁白的节奏里。本次接口返回音频与采样率，没有词语时间戳，因此字幕按整段旁白的起止时间显示；若需要逐句或逐词字幕，还要增加音文对齐步骤，并审阅切点。

背景配乐由程序原创合成：96 BPM 的轻节拍、温暖和弦和稀疏旋律，随段落变化并淡出收尾。混音使用 **Ducking**（自动压低）：旁白出现时降低音乐，停顿时缓慢恢复，让配乐有存在感，也给说话留出空间。

本片在检测到人声的时段，让旁白比音乐高至少约 10 dB，并检查音量峰值，避免超出可表示范围造成削波失真。数值帮助控制音量关系，配乐是否抢戏，仍要放进成片试听。

### 最后完成渲染与审阅

**渲染**（rendering）是按规则计算每一帧画面，再将画面和声音编码为视频文件。本片在本地使用 Remotion 的命令行渲染，三维画面通过浏览器绘制。[导出文档](https://www.remotion.dev/docs/cli/render)

在已经准备好源码、素材和依赖的 Remotion 项目中，可以用下面的命令导出视频。入口文件 `src/index.ts` 和注册的视频名称 `AICodeVideo` 按项目实际设置替换：

```sh
npx remotion render src/index.ts AICodeVideo output/video.mp4 --codec h264
```

初次使用可从 [Remotion 官方入门](https://www.remotion.dev/docs/)创建项目。官方也提供 [Agent Skills](https://www.remotion.dev/docs/ai/skills)，让编程助手按工具约定生成和修改视频。

## 四、程序能执行，内容仍需要判断

代码动画适合有明确结构的表达。文字、图形、数据和运动轨迹可以直接控制；同一份实现也能改文案、改配色或调整时间。

它的边界同样明确：写实表演或复杂角色动作需要合适的素材与制作方式；代码可运行，也不能保证概念准确、构图舒服或讲解节奏合适。

:::tip[审阅时看三个结果]
**内容**：概念是否讲对，示意是否交代了边界。

**画面**：文字是否清楚，关键对象是否被遮挡，运动是否帮助理解。

**声音与时间**：旁白是否自然、完整，配乐是否抢戏，字幕是否跟得上，镜头是否在讲完前切走。
:::

本次成片包含 15 段分镜，导出为 **1920 × 1080、30 FPS、约 2 分 50 秒**的 MP4，采用 H.264 视频编码和 AAC 音轨。文件完整解码检查通过，并检查了各场景的代表画面。

这些检查验证了文件和制作链可以工作。表达质量还需要完整观看后判断，这个案例也不足以证明它适合所有视频，或比所有其他方式更省时间。

## 五、这支视频，就是一次实践

回到开头：你刚才看到的讲解稿、分镜与动画代码，都由 AI 编写；画面由 Remotion 和 Three.js 渲染，旁白由语音合成工具生成。作者提出主题与参考风格，并在多轮试听和预览中给出修改意见。

**“AI 做视频”在这里意味着：把想法写成可执行、可预览、可修改的制作说明。** 成片用自己的制作过程解释了这条路线；博客保留原理、操作和边界，方便回头查阅。

第一次尝试，可以选一个值得讲清的概念，做一段只有文字、图形与运动的小动画。看过预览后，再把“哪里不清楚”变成一次具体修改。
